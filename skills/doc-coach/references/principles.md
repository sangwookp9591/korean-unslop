# 자료 구성 원칙과 그 한계

비즈니스 발표·보고서 작성에 널리 쓰이는 실무 원칙을 출발점으로 쓰되, 그대로 강제하면 획일적이고 읽기 어려운 자료가 되는 부분은 조정한다. 이 원칙들을 "맥킨지·BCG의 공식 표준"처럼 소개하지 않는다. 출처가 확인된 것은 출처를 붙이고, 나머지는 "실무에서 널리 쓰는 원칙"으로 말한다.

## 다섯 원칙: 적용할 부분과 조정할 부분

| 원칙 | 적용할 부분 | 조정할 부분 |
|---|---|---|
| 결론 먼저 | 의사결정용 보고에서는 결론 → 근거 → 상세가 유용하다 | 모든 자료를 문제 → 해결 → 효과로 고정할 필요는 없다. 전제, 한계, 반대 근거는 당장 행동으로 이어지지 않아도 남긴다 |
| 한 장표, 한 메시지 | 제목만 읽어도 논리가 이어지게 구성한다 | 한 주장을 뒷받침하는 여러 근거는 한 장에 함께 둘 수 있다. 목차와 참고자료까지 주장형 제목일 필요는 없다 |
| 개조식·체언 종결 | 짧은 항목, 라벨, 성과 요약에 쓴다 | 모든 문장을 명사형으로 바꾸지 않는다. 원인, 조건, 책임 주체가 흐려지면 문장으로 푼다 |
| 3분할 박스 | 나란한 세 항목을 비교할 때 쓴다 | 매 장표를 세 상자로 만들지 않는다. 추세는 차트, 일정은 시간축, 절차는 흐름도처럼 내용의 관계에 맞춘다 |
| 숫자 강조·색 절제 | 강조의 우선순위와 일관성을 지킨다 | 숫자 크기보다 비교 기준, 기간, 단위가 먼저다. "본문의 2~3배", "색 최대 3개"는 상황에 따라 조정하는 지침이다 |

## 가장 먼저 정할 것: 전달 방식

PPT와 PDF는 파일 형식일 뿐, 전달 방식은 따로 정해야 한다. 발표자가 설명하는 장표와 혼자 읽어도 이해해야 하는 자료는 필요한 설명의 양이 다르다. Duarte도 발표용 슬라이드와 읽기 위한 시각 문서(slidedoc)를 구분한다.

| | 발표용 장표 | 읽는 자료 (배포용 보고서, slidedoc) |
|---|---|---|
| 설명하는 사람 | 발표자 | 자료 자체 |
| 장당 글 | 적게. 핵심 메시지와 시각 자료. 설명은 발표자 노트로 | 혼자 읽어도 이해될 만큼. 관계를 문장으로 풀어 쓴다 |
| 제목 | 주장형 제목이 흐름을 끈다 | 주장형 제목 + 본문이 근거를 설명한다 |
| 용어·약어 | 말로 풀 수 있다 | 처음 나올 때 정의한다 |
| 출처·기준일 | 장 하단에 짧게 | 빠짐없이. 표와 차트마다 |
| 요약 | 마지막 요청 장 | 맨 앞 요약(Executive summary) |
| 발표 후 배포 | 발표용 장표를 그대로 보내면 설명이 비어 있다. 노트를 본문으로 옮긴 배포판을 따로 두거나, 부록에 설명을 붙인다 | |

## 제작까지 볼 때 함께 볼 것

- 목적: 누가 읽고, 읽은 뒤 어떤 판단이나 행동을 해야 하는가
- 근거 설계: 주장과 데이터의 연결, 출처, 기준일, 단위, 가정, 한계
- 시각화 선택: 비교는 막대, 추세는 선, 구성비는 누적 막대나 100% 막대, 과정은 흐름도, 일정은 시간축
- 가독성: 열람 환경에 맞는 글자 크기, 여백, 대비, 색 말고도 구분할 수단(패턴, 라벨). Microsoft PowerPoint 접근성 지침 참고
- 출력 검수: 실제 PPT와 PDF를 열어 글꼴, 줄바꿈, 잘림, 링크를 확인하고, PDF는 텍스트 선택과 읽기 순서를 점검한다. Adobe 접근성 PDF 지침 참고
