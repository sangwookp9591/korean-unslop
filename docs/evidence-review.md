# 근거 검토: 한국어 직접 반응과 연구

korean-unslop의 규칙을 정할 때 검토한 두 번째 조사다. 첫 번째 조사(긱뉴스, X·Threads, 국내 커뮤니티 74편, 기사·교열 기준)는 표지 목록을 만드는 데 썼고, 이 조사는 그 표지를 어디까지 믿고 어떻게 고칠지를 정하는 데 썼다.

## 조사 범위

| 구분 | 확보한 근거 | 읽을 때의 한계 |
|---|---|---|
| 한국어 직접 반응 | 7개 국내 커뮤니티와 브런치의 14개 페이지 | 국적·작성 방식 미검증, 대표 표본 아님 |
| X 관련 | 한국어 뉴스레터 1개, 연결된 X URL 3개 추적 | X 3개 모두 403. 원문 직접 확인 0건 |
| 연구 | 한국어 관련 논문 2편의 초록, 영어 연구 1편의 방법·논의·한계 | 연구 언어·과제 범위를 넘어 일반화하지 않음 |
| 출발점 | Martin Fowler 원문과 사용자가 준 긱뉴스 글 | 해외 원문·번역 댓글과 국내 직접 댓글을 구분 |

핵심 자료는 총 19개 출처다. 여러 커뮤니티를 검색했지만 모든 커뮤니티를 조사한 것은 아니다. 특히 X와 접근 제한이 있는 커뮤니티에 공백이 있다. 부정적 경험을 찾는 검색어를 사용했으므로 불쾌감의 보편성이나 발생 비율을 추정할 수 없다.

## 1. 사람들은 무엇을 AI 문체로 인식했나

| 단서 | 한국어 이용자의 반응 | 스킬에 반영한 판단 |
|---|---|---|
| 반복되는 과장·대조 | 브런치 작성자는 여러 매체의 '단순한 A가 아니다' 구조를 보며 읽기를 멈추는 피로를 설명했다. | 실제로 바로잡는 오해가 없는 대조를 덜어낸다. (K02, patterns A2) |
| 자동 칭찬·감탄 | 디시 이용자는 질문에 돌아온 강한 칭찬을 민망하게 느꼈다. | 요청에 답하는 데 필요하지 않은 인물 평가를 줄인다. (K03, A3) |
| 정형적인 리뷰 리듬 | 더쿠 이용자는 조사 생략, 감탄과 이모지, 장문의 설명과 추천 결말을 함께 지적했다. | 단어 하나보다 도입부터 결말까지의 반복 구조를 본다. (K04, B3) |
| 시도 때도 없이 끊는 단문 | 문피아 독자는 짧게 끊는 문장이 이어질 때 위화감과 답답함을 느낀다고 적었다. | 짧은 문장을 늘리는 대신 문장 연결과 장면의 호흡을 살핀다. (K05, C11) |
| 높임 수준의 혼용 | 블라인드 작성자는 자신이 존댓말을 쓰는데 답변은 반말과 존댓말을 섞어 불쾌하다고 했다. | 관계에 맞는 높임을 유지한다. (K06, A6) |
| 추상적이고 큰 비유 | 오르비에서는 같은 문장을 좋은 표현으로 칭찬하는 글과 AI스럽다고 비판하는 댓글이 공존했다. | 비유의 필요성과 독자를 판단하고, 취향 차이를 생성 여부의 증거로 삼지 않는다. (K14, D8) |
| 익숙하지 않은 의인화·어휘 | 긱뉴스 직접 댓글에서 한국어 AI 설명의 의인화와 드문 표현이 언급됐다. | 낯선 표현이 뜻을 가릴 때 행위·대상을 직접 설명한다. (K07, D8) |

이 표는 이용자가 보고한 인식이다. 특정 문체를 썼다는 사실만으로 AI 작성 여부를 확인할 수는 없다. 번호를 붙인 개인 메모가 스스로 챗지피티처럼 보인다는 더쿠 글과, AI 표지 때문에 본문까지 의심받았다는 문피아 작성자의 진술도 함께 검토했다.

## 2. '인지 부하'라는 말로 묶기 전에 구분할 것

커뮤니티의 피로 호소는 중요한 관찰이지만 실험으로 측정한 인지 부하는 아니다. 아래 구분은 이번 자료를 스킬로 옮기기 위한 해석 틀이다. 각 비용의 크기나 원인 효과를 측정한 결과는 아니다.

| 독자가 해야 하는 추가 작업 | 글에서 나타나는 문제 | 편집 방향 |
|---|---|---|
| 필요한 정보 골라내기 | 서론·일반론·재진술 속에서 답을 찾음 | 정보 전달 글에서는 답과 요청을 앞세우고 중복을 제거 |
| 문장의 관계 복원하기 | 원인·조건·대조가 빠진 채 문장만 나열됨 | 원문에 있는 관계를 조사와 연결 표현으로 드러냄 |
| 말의 대상 알아내기 | 추상 명사, 불분명한 지시어, 낯선 비유 | 익숙한 동사와 명확한 대상을 사용 |
| 사실과 확신의 정도 확인하기 | 근거 없는 단정, 출처 없는 주장 | 출처와 제한을 보존하고 사실 공백을 따로 표시 |
| 말하는 관계 조정하기 | 과한 칭찬, 갑작스러운 반말, 요청 밖의 친밀감 | 상대와 용도에 맞는 말투 유지 |
| 읽을 가치 판단하기 | 어느 글이나 같은 목소리, 작성자의 판단이 안 보임 | 제공된 관점·경험·취향을 보존하고 꾸며 넣지 않음 |

앞의 세 항목은 문장의 이해 과정, 뒤의 세 항목은 검증·관계·신뢰와 관련된다. 이들을 하나의 'AI 문체 점수'로 합치면 무엇을 고쳐야 하는지 흐려진다. 국내 직접 반응에서도 읽기를 회피하거나 다시 요약하려는 경험이 보이지만(긱뉴스의 직접 회피 경험, 재요약 반응), 이를 신경과학적 사실로 표현해서는 안 된다.

문장 단위로는 지나치게 압축되어 있고, 글 전체로는 중복이 많을 수도 있다. 따라서 '정보 밀도를 높여라'만으로는 부족하다. 새 정보가 없는 문장은 줄이고, 이해에 필요한 관계는 풀어 써야 한다. 이는 아래 연구를 참고해 제안한 편집 원칙이다.

## 3. 연구가 지지하는 것과 지지하지 않는 것

**한국어 대학 과제 69편 비교** (박종향·김은영, 2025)
2021년과 2025년 과제를 비교한 연구는 AI 활용 글의 문장이 더 짧고 어휘 다양성이 낮았다고 보고한다. 접속부사의 전체 빈도·다양성에는 유의미한 차이가 없었다. 이 결과는 'AI는 항상 장문을 쓰며 접속사를 많이 쓴다'는 단정을 경계하게 한다. 서로 다른 연도 집단을 비교했으므로 AI만의 인과 효과를 분리한 실험은 아니다.

**한국어 문학 번역의 독자 반응** (배유진·김순영, 2025)
추리소설 세 장면의 번역 비교에서 문장 구조·리듬은 AI 번역 선호가 52.3%, 구두점·시각적 호흡은 59.3%였다. 특정 번역 과제에서 규칙적인 리듬이 장점이 될 수 있다는 반례다. 한국인 전체의 선호나 모든 AI 글의 우월성으로 확대할 수 없다. 이 조사에서는 논문의 초록을 확인했으며 설문 세부사항은 추가 검토가 필요하다.

**영어 생성문과 언어 처리 특징** (Clark 외, 2026)
2026년 사전공개 연구는 드문 단어 조합, 명사 연결, 긴 구문 의존 관계 등 처리 난도와 관련된 특징을 분석했다. 길이 페널티가 문법 선택에 영향을 줄 수 있다는 모델 실험도 포함한다. 한국어 독자의 읽기 부담을 직접 측정한 연구는 아니며, 저자들도 언어·모델·주제 범위의 제한을 명시했다. '무조건 줄이기'보다 관계를 분명히 쓰는 편집을 고려할 근거로 사용했다.

## 4. X에서 확인한 범위

한국어 뉴스레터는 ChatGPT의 칭찬 말투가 밈으로 쓰이는 모습을 소개하고 여러 X 캡처의 출처를 연결했다(Trend A Word #414). 이 정도로는 특정 말투가 사람들이 알아보는 표지가 되었다고 볼 수 있다. 그러나 밈을 올린 행위가 실제 불쾌감이나 읽기 피로의 표현이라고 단정할 수는 없다.

연결된 X 원문 세 건은 모두 403 응답으로 본문을 가져오지 못했다. 뉴스레터 설명과 출처 링크를 확인한 간접 자료로만 남겼다. 따라서 X까지 충분히 망라한 조사라고 부를 수 없다. 접근 가능한 원문을 추가 확보하면 현재 스킬의 '감정·말투' 규칙을 더 세밀하게 검증할 수 있다.

## 5. 스킬에 넣은 규칙

스킬의 기본 동작은 최소 편집이다. 첫 문장부터 전부 다시 쓰는 대신 독자가 멈출 만한 구절을 찾아 수정한다. 사실과 조건이 빠지지 않도록 원문과 대조하며, 원래 자연스러운 글은 그대로 둘 수 있다.

- 정보 전달 글에서는 답·요청·결정을 먼저 제시한다.
- 흐린 지시 대상과 빠진 문장 관계를 분명하게 한다.
- 뜻을 가리는 명사 연결과 추상어를 풀어 쓴다.
- 근거 없는 과장과 실질적인 대조가 없는 수사를 덜어낸다.
- 칭찬·공감·높임의 강도를 독자와 관계에 맞춘다.
- 길게 얽힌 문장은 나누고, 잘게 끊긴 문장은 연결한다.
- 표·목록·강조는 글의 용도에 맞춰 사용한다.
- 글쓴이의 판단·취향·목소리와 모든 사실 조건을 보존한다.

## 6. 넣지 않은 방식

| 넣지 않은 방식 | 이유 |
|---|---|
| '단순히', '또한', '이를 통해', 쉼표를 전부 금지 | 정상적인 대조·연결·호흡까지 손상할 수 있음 |
| 무조건 짧게 쓰고 일정 비율 이상 삭제 | 조건·인과가 빠지거나 명사만 이어 붙일 수 있음 |
| 세 항목 목록·소제목·표 전부 제거 | 절차와 비교에서는 읽기를 도와줌 |
| 오타·반말·비속어로 인간처럼 보이게 만들기 | 원래 목소리와 관계를 훼손함 |
| 경험·숫자·감정을 새로 넣어 구체화 | 문체 개선 과정에서 사실을 지어낼 수 있음 |
| 탐지 점수나 'AI일 확률' 출력 | 가독성과 생성 여부를 혼동함 |
| 친절함을 모두 제거 | 공감을 장점으로 평가하는 반응도 있음(더쿠 후기) |

## 7. 추가 검토: Clark 외 2026 세부 내용과 실무자 반론

### 연구 내용

AI가 작성한 영어 대화, 코딩 관련 설명, 에세이를 분석한 결과, 사람이 읽고 이해하는 데 부담을 주는 표현이 더 자주 나타났다.

- **분석 대상:** 인간의 언어 처리 난도와 상관관계가 알려진 심리언어학적 특징(목적격 관계절, 긴 구문 의존 관계, 출현 빈도가 낮은 n-그램 등). 다양한 분야의 AI 생성 텍스트 말뭉치를 새로 구축하고, 왕복 번역으로 바꿔 쓴 문장 및 인간의 글과 비교했다.
- **모델:** 최상위권 및 준최상위권 모델 9개(Claude Sonnet 5, Opus 5, Opus 5.5, Fable 5, GPT-5.6 sol, terra, luna, GLM-5, Kimi K2.5)와 소형 공개 모델 5개(Llama 3.1 8B base/Instruct, Olmo 3 7B base/Instruct/Think). 대화 데이터는 기본 모델을 제외한 12개 모델에 10개 주제를 적용한 120개 대화.
- **결과:** 9개 모델 모두 인간의 글보다 (1) 무생물 주어와 유생물의 행동을 나타내는 동사의 결합, (2) 출현 빈도가 낮은 n-그램을 더 많이 썼다. 대화에서는 대부분의 모델이 더 긴 구문 의존 관계, 명사 연쇄, 축약된 목적격 관계절도 더 많이 썼다. 모델 계열 간 차이가 컸다.
- **왕복 번역:** 같은 문장을 영어에서 일본어로 번역했다가 다시 영어로 옮기면 이런 특징이 줄었다. 내용뿐 아니라 AI가 고르는 표현 방식에 차이가 있다는 뜻이다.
- **가설:** 인간의 언어는 성공적인 의사소통에 최적화되는 반면, AI 생성 텍스트는 수학, 코드, 추론처럼 정보 밀도를 높이는 압력이 작용하는 목표에 점점 더 최적화된다.
- **개념 증명:** 작은 모델에 긴 답변을 벌점으로 주는 강화학습(GRPO)을 적용하자, 학습하지 않은 일부 문장 구조에서도 짧은 표현을 선호했다. 압축 압력이 문법 선택까지 바꿀 수 있다.

### 실무자 반론과 관찰 (해외 커뮤니티 댓글 번역)

- **정반대 체감:** "글이 지나치게 빽빽해서 어렵다"는 가설과 달리, 오히려 정보 밀도가 너무 낮아서 읽기 어렵다는 반응이 있었다. 정보 전달보다 "좋은 글처럼 보이기"에 최적화된 느낌이라는 것이다.
- **좋은 글처럼 보이는 형태:** 인간 피드백 기반 강화학습이 평가자의 첫인상에 맞춰졌을 수 있다. 목록과 제목, "결정적 증거" 같은 흥미로운 표현, 길고 정보가 풍부해 보이는 형태는 빠르게 평가하기 쉽지만 독자에게 유용한지는 알 수 없다.
- **기계적 간결성 규칙:** Gmail의 글쓰기 도움 기능은 문장마다 평균 1.3개꼴로 간결하게 쓰라는 제안을 냈지만 거의 전부 형편없었다. 작문 규칙을 모든 절에 기계적으로 적용하면서 호흡, 핵심 단어 강조, 감정 조절을 무시했다. 간결함에 보상하는 미세조정에 글 전체의 흐름을 평가하는 균형추가 없는 것 같다는 지적이다.
- **추상 주어:** "텍사스는 처리된 하수 슬러지를 비료로 허용하지만, PFAS 검사를 의무화하는 법안은 진전되지 못했다" 대신 "주 정부는 해당 법안을 진전시키지 못했다"처럼 행위자를 드러내야 한다.
- **군더더기 안내 문장:** 빼 달라고 여러 번 요청해도 "여기서 이야기가 더 흥미로워집니다", "증거를 비교하면 다음과 같습니다" 같은 문장이 계속 들어온다.
- **사실을 바꾸는 군더더기 동사:** "주교가 교황을 만나 미사를 논의했다"보다 "주교가 교황과 미사를 논의했다"가 명확하다. 불필요한 "만났다"는 우연한 만남처럼 읽힌다.
- **타동사의 자동사화:** "The user presses a button, and the form submits."처럼 목적어 없이 쓰면 기술 문서에서 독자가 추측해야 한다. 반론으로, "the door opened", "wait for the code to compile"처럼 자리 잡은 용법은 자연스럽고, 문제는 가끔 쓰는 것이 아니라 과도한 반복이라는 의견이 있었다("X가 아니라 Y다"도 원래 괜찮은 표현이었지만 남용되며 상투어가 됐다).
- **여러 조건 유지의 어려움:** LLM은 국소적인 목표는 달성하지만 여러 조건을 동시에 유지하지 못하고, 단어가 묘사하는 현실 구조를 놓쳐 비논리적인 비유를 만든다.
- **프롬프트의 한계:** 더 충실하고 상세하게 써 달라고 여러 차례 지시해도 실패했다는 경험이 있다. 프롬프트로 문체를 바꿀 수 있어도 항상 성공하거나 오래 유지된다는 보장은 없다.

### 스킬에 반영한 것

- C12(행위자가 숨은 문장): 무생물 주어와 사람 행동 동사, 행위자가 빠진 문장, 사실을 바꾸는 군더더기 동사. 자리 잡은 표현("컴파일이 끝나면", "빌드가 깨졌다")은 남긴다.
- C6(명사화)에 명사 연쇄와 압축 압력 근거를 추가했다.
- A5(예고·메타 발화)에 군더더기 안내 문장을 추가하고 스크립트에서도 센다.
- B3(과잉 구조)에 "좋은 글처럼 보이는 형태" 배경을, D7(상투 어휘)에 "결정적 증거", "흥미롭게도"를 추가했다.
- "하지 않는 것"에 "문장마다 간결성 규칙을 기계적으로 적용"을 추가했다. 압축과 장황함은 동시에 나타날 수 있으므로, 새 정보가 없는 문장은 줄이고 이해에 필요한 관계는 풀어 쓰는 원칙을 유지한다.
- 쓰기 모드에서 지시만으로 문체가 유지된다고 믿지 않고, 초안을 쓴 뒤 스크립트로 다시 센다.
